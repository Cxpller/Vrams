**状态**: 框架已确认，数据模型设计中
**日期**: 2026-11-10
**取代**: `产品需求文档.md`（v3.0）、`开发计划.md` 中的范围与路线（旧文档保留作历史参考）

## 1. 为什么重构

- 原设计只是"zip 管理库"：复制到库目录、标签、Booth 封面。
- 参考了两个同类项目的**功能设计**（不借鉴技术、不复制代码——两者许可证均不允许）：
  - VRCAL（NecoAya/VRCAL-VRChat-Asset-Library）
  - MioVRC（CokoIya/MioVRC_AssetManager）
- 同时借重写之机学习 React。

## 2. 技术栈

| 层 | 选型 | 变化 |
|----|------|------|
| 桌面壳 | Tauri v2 | 不变 |

## 3. 已确认的关键决策

| 决策 | 结论 |
|------|------|
| 入库方式 | 设置一个或多个**素材库目录**，扫描后**原地索引**；从下载目录等处拖入的文件**移动**到素材库后再索引 |
| 元数据 | **三层**：扫描层（文件名/大小/规则推断）、在线层（Booth 抓取）、手动层（用户修改）；展示时手动层优先，重新扫描/匹配不覆盖用户修改 |
| 网盘 | 只记录链接 + 提取码，一键在浏览器打开；分享链接解析以后再考虑 |
| 闲鱼 | 只做"在浏览器中搜索"跳转，不抓取 |
| AI 分类 | 先用规则（文件名、Booth 标签）；以后再加用户自填 API Key（OpenAI 兼容格式） |
| 删除 | 进回收站，可撤销 |
| 不做 | 社交社区、试衣间/照片找衣服/视频工作室、MCP、Booth 登录与购买同步、愿望单、Gumroad/Jinxxy、应用内抓取闲鱼 |

| ① 资产库 | 库目录、扫描、拖入导入、包内文件列表、缺失检测 | 扫描层 |

| ④ 查找浏览 | 搜索、筛选、排序、封面、预览 | 合并三层展示 |
| ⑤ 使用 | 打开文件、在资源管理器显示、导入 Unity | — |
| ⑥ 系统 | 设置、首次引导、回收站与撤销、备份、多语言与主题、更新 | — |

## 6. 数据模型（第一版）

**核心思路**：资产 = 逻辑上的"商品"；文件 = 磁盘上的物理条目。一个资产对应多个文件（一对多，外键实现）。

```
library_roots 1──多 asset_files 多──1 assets
                         1
                         │多
                   archive_entries
```

| 表 | 主要列 | 说明 |
|----|--------|------|
| `library_roots` | id, path UNIQUE, name, last_scanned_at | 素材库目录 |
| `assets` | id, scan_name, scan_category, created_at | 资产，只放**扫描层** |
| `asset_files` | id, asset_id FK, root_id FK, rel_path, kind, size, mtime, missing；UNIQUE(root_id, rel_path) | 磁盘条目；kind ∈ folder/zip/7z/rar/unitypackage |
| `archive_entries` | id, file_id FK, path, is_dir, size | 包内文件列表（文件夹也按"包"处理） |

**设计决定**

- **相对路径**：`rel_path` 相对于素材库目录，库目录搬家只改 `library_roots` 一行。
- **变化检测**：重新扫描时 `size` + `mtime` 未变则跳过，不重新解析包内文件。
- **缺失标记**：文件找不到置 `missing = 1`，不删记录。
- **三层元数据**拆三张表：`assets`（扫描层）、`asset_online`（在线层，第三版 V003 加）、`asset_user`（手动层，第二版 V002 加）；展示时 `COALESCE(u.x, o.x, a.scan_x)`。第一版只建上面 4 张表，其余用迁移逐步加。
- **多对多**（标签，第二版）：`tags` + `asset_tags(asset_id, tag_id)` 组合主键、两侧 `ON DELETE CASCADE`；标签分组为一对多：`tag_groups` + `tags.group_id`。

**扫描规则（什么算一个资产）** — 方案 B：从库目录递归往下：

1. 压缩包 / unitypackage（.zip/.7z/.rar/.unitypackage）→ 一个资产。
2. 文件夹**直接**含素材文件（fbx、prefab、贴图等）→ 这个文件夹是一个资产，不再往下钻。
3. 否则视为**分类目录**（如"衣服"、"头发"），继续往下找；其名称可作为 `scan_category` 的推断依据。
4. 边界情况（一个商品文件夹里放了多个 unitypackage 等）留给 P1"手动纠正 / 合并"。
