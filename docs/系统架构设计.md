## 1. 技术栈

| 层 | 技术选型 | 说明 |
|----|----------|------|
| 前端框架 | Vue 3 + TypeScript + Composition API | `<script setup lang="ts">` 模式 |
| UI 库 | Element Plus | 按需引入 |
| 桌面框架 | Tauri 2 | Rust 后端 + WebView 前端 |
| 数据库 | SQLite | 通过 Rust rusqlite / sqlx 操作 |
| 压缩包解析 | Rust（zip crate + tar + flate2） | 只读解析 .zip / .7z / .unitypackage |
| HTTP 请求 | Rust（reqwest + scraper crate） | 下载 Booth 预览图 |
| 文件操作 | Rust（std::fs） | 库目录文件复制与清理 |
| 包管理 | pnpm | 禁止使用 npm/yarn |

## 3. 存储策略 — 复制到库目录

### 3.1 核心原则

```
VRAMS 是资产的"家"——导入时复制到库目录，用户可清空下载文件夹。
```

- 用户导入 → VRAMS **复制文件**到库目录 `assets/{id}/`
- 原始文件可以选择移至回收站（默认勾选）
- 库目录在**首次启动**时由用户设定
- **设置中可修改路径**，修改时提示"需要迁移存量文件"

### 3.2 库目录结构

```
D:/VRAMS-Library/                    ← 用户首次启动时指定
├── assets/                          ← 资产文件
│   ├── 1/                           ← asset_id = 1
│   │   ├── Avatar-Kikyo.zip         ← 原始文件（原名保留）
│   │   └── Avatar-Kikyo-Hair.zip    ← 合并文件
│   ├── 2/
│   │   └── Outfit-Summer.zip
│   └── 3/
│       └── Free-Shader.7z
├── thumbnails/                      ← 预览图
│   ├── 1.jpg
│   └── 2.jpg
└── vrams.db                         ← SQLite 数据库
```

### 3.3 文件命名规则

| 场景 | 命名 |
|------|------|
| 导入时 | 保留原始文件名（可包含中文/空格/Unicode） |
| 重名冲突 | 自动追加编号：`file (1).zip` |
| 预览图 | `{asset_id}.jpg` |
| 合并文件 | 共用一个 `assets/{id}/` 目录 |

### 3.4 库目录迁移

当用户在设置中修改库目录时：

```
旧路径 → 新路径
1. 停止写操作
2. 复制整个 assets/ thumbnails/ vrams.db 到新位置
3. 更新 SQLite 中 assets 表路径字段
4. 标记旧路径为可删除（保留由用户手动清理）
```

### 3.5 删除资产

```
删除资产:
1. 删除 assets/{id}/ 整个目录
2. 删除 thumbnails/{id}.jpg
3. 清理数据库记录（级联删除）
```

## 4. 数据库设计

### 4.1 ER 图

```
┌──────────┐       ┌────────────┐       ┌──────────┐
│  assets  │       │ asset_tags │       │   tags   │
├──────────┤       ├────────────┤       ├──────────┤
│ id (PK)  │──1:N──│ asset_id   │──N:1──│ id (PK)  │
│ name     │       │ tag_id     │       │ name     │
│ source_url│      └────────────┘       │ group    │
│ thumbnail│                            └──────────┘
│ notes     │       ┌──────────────┐
│ created_at│       │  asset_files  │
│ updated_at│       ├──────────────┤
│ status    │──1:N──│ id (PK)      │
└──────────┘        │ asset_id     │
                    │ file_name    │
                    │ file_size    │
                    │ is_primary   │
                    │ internal_info│ ← 压缩包内文件清单（JSON，可选缓存）
                    │ created_at   │
                    └──────────────┘
```

### 4.2 核心表结构

```sql
-- 资产表
CREATE TABLE IF NOT EXISTS assets (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL,                        -- 用户可编辑的商品名
    source_url  TEXT,                                    -- Booth / 官网链接
    thumbnail   TEXT,                                    -- 预览图路径（thumbnails/{id}.jpg）
    notes       TEXT,                                    -- 用户备注
    status      TEXT    NOT NULL DEFAULT 'active',        -- active / deleted
    created_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);

-- 资产文件表（一个资产对应 N 个文件）
CREATE TABLE IF NOT EXISTS asset_files (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_id      INTEGER NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
    file_name     TEXT    NOT NULL,                      -- 文件名
    file_size     INTEGER,                               -- 字节数
    is_primary    INTEGER NOT NULL DEFAULT 0,             -- 1 = 主文件（主要用于展示）
    file_type     TEXT    NOT NULL DEFAULT 'zip',          -- zip / 7z / unitypackage
    internal_info TEXT,                                   -- 压缩包内文件清单（JSON，可选缓存）
    created_at    TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);

-- 标签表
CREATE TABLE IF NOT EXISTS tags (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT    NOT NULL UNIQUE,                   -- 标签名（如 "Kikyo"）
    group_name TEXT    NOT NULL DEFAULT '',                -- 分组（角色/类型/状态）
    created_at TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);

-- 资产-标签关联表
CREATE TABLE IF NOT EXISTS asset_tags (
    asset_id INTEGER NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
    tag_id   INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (asset_id, tag_id)
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_assets_name        ON assets(name);
CREATE INDEX IF NOT EXISTS idx_assets_status      ON assets(status);
CREATE INDEX IF NOT EXISTS idx_asset_files_asset  ON asset_files(asset_id);
CREATE INDEX IF NOT EXISTS idx_tags_group         ON tags(group_name);
CREATE INDEX IF NOT EXISTS idx_asset_tags_tag     ON asset_tags(tag_id);
```

### 4.3 数据库版本管理

```sql
PRAGMA user_version = 1;
```

迁移策略：
- 应用启动时检查 `PRAGMA user_version`
- 按顺序执行未应用的迁移脚本（migrations/V001__init.sql）
- 迁移脚本必须幂等（`IF NOT EXISTS` / `IF EXISTS`）

## 5. 导入流程详解

### 5.1 导入全流程

```
用户拖入文件
       │
       ▼
前端: 获取文件路径列表 → invoke("preview_import", { paths })
       │
       ▼
Rust: 扫描每个文件
  ├── 检测文件类型 (zip/7z/unitypackage)
  ├── 读取内部文件列表（不解压到磁盘）
  └── 检测是否为重复导入
       │
       ▼
前端: 导入审查窗口
  ├── 展示每个文件的信息和包内结构
  ├── 用户勾选 → 合并选中 → 拆开
  ├── 填写名称 / Booth URL
  └── 确认导入 → invoke("confirm_import", { items })
       │
       ▼
Rust: 执行导入
  ├── 为每个资产创建 assets/{id}/ 目录
  ├── 复制文件到对应目录
  ├── 若勾选"删除源文件" → 移至回收站
  ├── 写入 assets 表 + asset_files 表
  ├── 若填写了 URL → 自动触发预览图下载（后台）
  └── 返回导入结果
       │
       ▼
前端: 刷新卡片列表
```

### 5.2 导入审查窗口数据结构

```typescript
// 前端 → Rust (preview_import)
interface PreviewRequest {
  paths: string[];
}

// Rust → 前端 (预览结果)
interface PreviewItem {
  index: number;
  file_name: string;
  file_size: number;
  file_type: "zip" | "7z" | "unitypackage";
  internal_structure: FileNode[];  // 文件树
  has_unitypackage: boolean;       // 压缩包内是否含 .unitypackage
  is_duplicate: boolean;           // 是否已导入过
}

// 前端 → Rust (confirm_import)
interface ImportGroup {
  name: string;                // 资产名
  source_url?: string;         // Booth URL
  delete_originals: boolean;   // 是否删除源文件
  file_indices: number[];      // 预览结果中的索引（可多个 = 合并）
}
```

### 5.3 合并导入的存储

```
用户合并了 index 0 (Kikyo.zip) + index 1 (Kikyo-Hair.zip)
         │
         ▼
assets 表:  id=1, name="Avatar-Kikyo 套装"
         │
         ▼
asset_files 表:
  (id=1, asset_id=1, file_name="1/Avatar-Kikyo.zip",      is_primary=1)
  (id=2, asset_id=1, file_name="1/Avatar-Kikyo-Hair.zip", is_primary=0)
         │
         ▼
磁盘:
  assets/1/Avatar-Kikyo.zip
  assets/1/Avatar-Kikyo-Hair.zip
```

## 6. 压缩包解析机制

### 6.1 支持的格式与解析方式

| 格式 | 本质 | 解析方式 |
|------|------|----------|
| .unitypackage | gzip → tar | 读 pathname 文件，构建目录树 |
| .zip | zip 格式 | 读 Central Directory，列出文件路径 |
| .7z | 7z 格式 | 读 7z header，列出文件路径 |

### 6.2 解析原则

- **只读不解压**：读取文件列表，不提取文件内容到磁盘
- **按需触发**：导入时扫描快速信息，完整目录树在用户点击"查看结构"时才加载
- **读完即弃**：不缓存解析结果（可选：v1.2 后缓存到 `internal_info` 字段提速）

### 6.3 .unitypackage 的特殊处理

```
.unitypackage
  ├── GUID_1/
  │   ├── pathname    ← ★ 读取这个 (纯文本，如 "Assets/Models/Kikyo.fbx")
  │   ├── asset       ← ❌ 不读
  │   └── asset.meta  ← ❌ 不读
  ├── GUID_2/
  │   └── pathname    ← ★
  └── ...
```

只读 `pathname`，不读 `asset` 和 `asset.meta`。

### 6.4 "导入 Unity"对压缩包的处理

```
用户点击 zip 文件的"导入 Unity"
       │
  ┌─ 内有 .unitypackage？ ── 否 ──→ 提示"未发现 UnityPackage，请手动解压"
  │       是
  │
  ▼
Rust: 解压到临时目录（仅提取 .unitypackage 文件）
       │
       ▼
调用 opener::open(temp_path) → Unity 打开
       │
       ▼
Unity 关闭后 / 应用下次启动 → 清理临时目录
```

临时目录位置：`{temp_dir}/vrams/`（系统临时文件夹）

## 7. 预览图获取机制

### 7.1 流程

```
用户填写 Booth URL / 自动触发（默认开启）
       │
       ▼
Rust: reqwest GET → Booth 商品页 HTML
       │
       ▼
Rust: scraper 解析 <meta property="og:image" content="...">
       │
  ┌─ 找到？ ── 否 ──→ 静默失败，不干扰用户
  │    是
  │
  ▼
下载图片 → 保存到 thumbnails/{asset_id}.jpg → 更新 asset.thumbnail
       │
       ▼
通知前端 → 卡片刷新显示预览图
```

### 7.2 边界处理

| 情况 | 处理 |
|------|------|
| 用户关闭了自动下载（设置中） | 不请求网络 |
| 网络请求失败 | 静默失败，用户可手动上传 |
| 页面无 og:image | 静默失败，用户可手动上传 |
| 用户手动上传 | 覆盖任何自动下载的结果 |

## 10. 数据流

### 10.1 资产导入

```
用户拖拽 → Tauri drop event → invoke("preview_import", { paths })

Rust: 扫描 → 检测类型 → 读内部文件列表 → 去重检查
```

### 10.2 标签打标

```
       │
Rust: 删除旧关联 → 插入新关联
       │
前端刷新标签展示
```

## 11. 安全设计

| 关注点 | 措施 |
|--------|------|
| CSP 策略 | 必须配置合理 CSP（不允许 `csp: null`） |
| 数据本地化 | 所有数据存本地 SQLite，不上传 |
| 文件路径安全 | 库目录内按 asset_id 组织，防止路径遍历 |
| 网络请求 | 仅请求 Booth 的 og:image 资源，不执行远程脚本 |
| 用户输入 | 长度/内容校验后写入数据库 |
| 文件打开 | 通过 OS 默认程序打开，不解析执行 |
| 临时文件 | 导入 Unity 时提取的临时文件，应用退出时清理 |
| 删除操作 | 删除资产需二次确认，走回收站（系统级） |

## 12. 性能目标

| 场景 | 目标 |
|------|------|
| 应用冷启动 | ≤ 3s |
| 首页加载（1000 资产） | ≤ 1s |
| 搜索响应 | ≤ 500ms |
| 导入审查（扫描文件） | ≤ 1s（单文件）、≤ 3s（5 文件） |
| 单文件导入复制（100MB） | ≤ 2s |
| 压缩包目录解析（1000 文件） | ≤ 3s |
| 预览图下载 | ≤ 5s（取决于网络） |
| 库目录迁移 | 每 GB 数据 ≤ 30s |
