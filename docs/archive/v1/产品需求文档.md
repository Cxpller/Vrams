## 1. 项目概述

| 项目 | 内容 |
|------|------|
| 项目名称 | VRAMS (Virtual Reality Asset Management System) |
| 项目定位 | 面向 VRChat 用户及 Unity 创作者的本地化虚拟资产管理工具 |
| 系统目标 | 解决用户在长期使用 Unity、VRChat 进行模型修改过程中产生的大量数字资产难以管理、查找和复用的问题 |
| 目标平台 | Windows（离线桌面应用） |
| 用户模型 | **单机单用户** — 本机使用者即资产所有者，无多用户/登录/账号体系 |

## 2. 背景分析

### 2.1 用户积累的资产类型

- Unity Package 文件（.unitypackage）
- 角色模型、服装、发型等资源（以 .zip / .7z 分发）
- Shader、材质、动画文件
- Booth 等平台下载的压缩包

### 2.2 当前管理方式的痛点

| 方式 | 问题 |
|------|------|
| Windows 文件夹 | 文件命名混乱、无法预览内容、无分类体系 |
| 网盘 | 需要上传下载、离线不可用、不能看包内结构 |
| Excel 记录 | 维护成本高、需要手动更新、不能关联文件 |
| Downloads 堆积 | 下载后散落在系统下载目录，难以整理 |

### 2.3 核心洞察

用户从 Booth 等平台下载资产，**压缩包（.zip/.7z）是最常见的格式**，而非直接的 .unitypackage。用户需要一个"下载完直接拖进去"的工具，导入后统一管理，系统下载目录可以清空。

## 3. 用户定位

### 3.1 目标用户

- VRChat Avatar Creator
- Unity 模型修改用户
- 3D 资产收藏用户

### 3.2 用户画像

| 角色 | 描述 | 技术能力 | 核心动机 |
|------|------|----------|----------|
| 新手创作者 | 刚接触 VRChat avatar 制作，资产量 < 50 | 低 | 建立有序的资产库，清空杂乱的 Downloads |
| 资深创作者 | 长期制作模型，资产量 50–500+ | 中高 | 快速查找和复用已有资产，避免重复购买 |
| 资产收藏家 | 主要购买和整理资产，不深度修改 | 中 | 可视化管理收藏，了解自己有什么 |

## 4. 用户故事

### Epic A: 资产入库

```
As a 所有用户
I want 把下载的 .zip/.7z/.unitypackage 直接拖进应用就完事
So that 不用先解压再导入
```

```
As a 所有用户
I want 导入时填写资产名称和 Booth 链接
So that 以后知道这个资产是什么、从哪买的
```

```
As a 所有用户
I want 导入后文件自动复制到 VRAMS 库目录
So that 我可以清空 Downloads，系统整洁
```

```
As a 资深创作者
I want 同一个商品的多个分卷文件合并为一个资产
So that 一个商品一张卡片，不拆散
```

```
As a 所有用户
I want 在资产详情中查看压缩包内的文件结构
So that 不打开 Unity 也能知道里面有什么
```

### Epic B: 资产浏览与查找

```
As a 所有用户
I want 用卡片网格浏览所有资产，看到封面和名称
So that 一眼扫过去就能找到想要的
```

```
As a 所有用户
I want 按标签筛选资产
So that 从几百个资产中快速缩小范围
```

```
As a 所有用户
I want 搜索框输入关键词就能搜到资产
So that 记得名字时不用翻页
```

### Epic C: 分类与标签

```
As a 所有用户
I want 给资产打自定义标签（角色名/类型/状态）
So that 跨维度组织资产
```

```
As a 所有用户
I want 用标签筛选器快速选择多个标签组合
So that 找到"Kikyo 角色 + 衣服 + 已购买"的资产
```

### Epic D: 资产管理

```
As a 所有用户
I want 在资产详情中对每个关联文件独立操作
So that 想导入 Unity 哪个就开哪个
```

```
As a 所有用户
I want 右键打开文件所在文件夹
So that 需要手动处理时能直接定位
```

```
As a 所有用户
I want 一键导入 Unity（自动识别包内 .unitypackage）
So that 不用在文件管理器里自己翻
```

```
As a 所有用户
I want 编辑资产的名称、标签、链接、预览图
So that 资产信息随着使用不断完善
```

```
As a 所有用户
I want 删除资产时清理所有关联文件和预览图
So that 不留残留文件
```

## 5. 用例分析

### UC-01: 导入资产

| 项目 | 内容 |
|------|------|
| 参与者 | 所有用户 |
| 前置条件 | 应用已启动 |
| 触发条件 | 用户拖拽文件到窗口 / 点击"导入"按钮批量选择文件 |

**正常流程 — 单文件**:
1. 用户拖入一个 .zip / .7z / .unitypackage 文件
2. 系统识别文件类型，快速扫描包内结构（仅文件列表）
3. 弹出导入审查窗口，显示文件信息和包内结构
4. 用户填写资产名称（默认文件名）、Booth URL（可选）
5. 用户确认导入
6. 系统复制文件到 VRAMS 库目录 `assets/{id}/`
7. 写入数据库资产记录
8. 若勾选"删除源文件"，将原始文件移至回收站
9. 卡片列表显示新资产

**正常流程 — 多文件（同一商品分卷）**:
1. 用户拖入多个文件
2. 系统扫描每个文件的内含结构
3. 导入审查窗口显示文件列表
4. 用户勾选属于同一商品的多个文件 → 点击"合并选中"
5. 选中文件折叠为一个组，编辑统一名称和 Booth URL
6. 用户确认导入
7. 系统为每个文件创建 `assets/{id}/` 目录，统一归入同一资产 ID
8. 写入 assets 一条记录 + asset_files 多条记录
9. 若勾选"删除源文件"，将原始文件移至回收站

**正常流程 — 多文件（不同商品）**:
1. 用户拖入多个文件
2. 导入审查窗口显示每个文件独立一行
3. 用户保持默认（不合并），各自填写名称和 URL
4. 确认导入 → 每个文件各自为一个独立资产

**扩展流程**:
- 2a. 文件格式不支持 → 提示"暂不支持此格式"
- 2b. 文件已存在于库目录（同名+同大小）→ 提示"该文件已导入过"，跳过或强制重新导入
- 3a. 压缩包损坏 → 提示"文件可能已损坏，但可继续导入（无法查看内部结构）"

**后置条件**: 文件已复制到库目录，数据库已写入

**补充：导入审查窗口交互**
```
───────────────────────────────────────────────
  导入资产
───────────────────────────────────────────────

  已检测到 3 个文件:

  ☐  Avatar-Kikyo.zip                  57 MB    ← 内扫描到 .unitypackage
  ☐  Avatar-Kikyo-Hair.zip             12 MB
  ☐  Outfit-Summer.zip                 88 MB

  ┌─────────────────────────────────────────────┐
  │  [🗂 合并选中]    [拆开]                    │
  └─────────────────────────────────────────────┘

  合并后:

  ☑  📁 Avatar-Kikyo 套装 (2个文件)         69 MB
        ├── Avatar-Kikyo.zip
        └── Avatar-Kikyo-Hair.zip
        商品名: [Avatar-Kikyo 套装           ]
        Booth  : [https://booth.pm/...       ]

  ☐  Outfit-Summer.zip                     88 MB
        商品名: [Outfit-Summer                ]
        Booth  : [                            ]

  ☑ 导入完成后删除源文件

  [✔ 确认导入 3 个资产]  [取消]
───────────────────────────────────────────────
```

### UC-04: 查看压缩包结构

| 项目 | 内容 |
|------|------|
| 参与者 | 所有用户 |
| 前置条件 | 资产已导入且文件在库目录中存在 |
| 触发条件 | 用户点击资产详情中某个文件的"查看结构" |

**正常流程**:
1. 系统实时读取文件
2. 解析内部目录结构（.unitypackage → 读 pathname；.zip/.7z → 读文件列表）
3. 按目录层级构建文件树
4. 在弹窗/侧栏中以可展开的文件树展示

**扩展流程**:
- 1a. 文件不存在 → 提示"文件已被删除或移动"，引导用户检查
- 2a. 文件损坏或格式异常 → 显示"无法解析"
- 4a. 包内文件过多（>200）→ 默认折叠所有层级

### UC-07: 获取预览图

| 项目 | 内容 |
|------|------|
| 参与者 | 所有用户 |
| 前置条件 | 资产已存在 |
| 触发条件 | 用户填写 Booth URL 后 / 用户点击"选择本地图片" |

**正常流程（自动）**:
1. 用户填写 Booth URL
2. 系统自动请求该页面，获取商品预览图（og:image）
3. 保存图片到 `thumbnails/{id}.jpg` → 关联到资产
4. 卡片刷新显示预览图

**正常流程（手动）**:
1. 用户点击"选择本地图片"
2. 从文件选择器选择 PNG/JPG
3. 缩略图保存并关联到资产

**扩展流程**:
- 2a. 自动下载失败（无网络/Booth 改版）→ 回退到手动模式，不阻塞
- 2b. 页面无预览图 → 提示"未找到预览图，请手动选择"

### UC-08: 导入 Unity

| 项目 | 内容 |
|------|------|
| 参与者 | 所有用户 |
| 前置条件 | 资产在库中，文件存在 |
| 触发条件 | 用户在资产详情中点击某个文件的"导入 Unity" |

**正常流程（单文件）**:
1. 点击文件旁的"导入 Unity"按钮
2. 系统检查文件是否存在
3. 如果文件是 .unitypackage → 直接调用 OS 打开
4. 如果文件是 .zip/.7z → 检查内部是否有 .unitypackage
   - 有 → 提取到临时目录 → 打开该 .unitypackage
   - 无 → 提示"未在压缩包内发现 UnityPackage，请手动解压"

**扩展流程**:
- 2a. 文件不存在 → 提示"文件已丢失"
- 4a. Unity 未安装 → 提示"未检测到 Unity"

---

### UC-09: 删除资产

| 项目 | 内容 |
|------|------|
| 参与者 | 所有用户 |
| 前置条件 | 资产已在库中 |
| 触发条件 | 用户在资产详情页点击"删除" |

**正常流程**:
1. 系统弹出确认对话框："将删除此资产及其所有关联文件，不可恢复"
2. 用户确认删除
3. 系统删除库目录下 `assets/{id}/` 整个文件夹
4. 系统删除关联的预览图
5. 系统清理数据库记录（assets + asset_files + asset_tags）
6. 返回资产列表

**扩展流程**:
- 2a. 用户取消 → 不执行任何操作

## 7. 迭代路线

```
v1.0 (MVP)          v1.1               v1.2               v2.0
◄──────────►   ◄──────────►     ◄──────────►     ◄──────────►
  现在             Month 1-2         Month 3-4          Month 5+
```

### v1.0 — MVP

**目标**: 让用户能把资产拖进库、打上标签、能找能用。

**包含**:
- ✅ 拖拽/选择导入 .zip/.7z/.unitypackage
- ✅ 导入审查窗口（填写名称/URL/删除源文件选项）
- ✅ 文件复制到 VRAMS 库目录
- ✅ 首次启动引导设置库目录
- ✅ 卡片网格浏览 + 空状态引导
- ✅ 创建/编辑/删除标签，为资产打标签
- ✅ 名称搜索
- ✅ 资产详情展示（单文件）
- ✅ 删除资产（清理库文件 + 数据库）
- ✅ 手动选择本地预览图 + 骨架占位
- ✅ 来源链接填写 + 一键浏览器打开
- ✅ 导入 Unity（.unitypackage 直接打开）
- ✅ 打开所在文件夹

**MVP 不包含**:
- ❌ 合并多文件为同一资产
- ❌ 批量自动从 Booth 下载预览图
- ❌ 压缩包目录树解析
- ❌ 标签分组
- ❌ 压缩包内提取 .unitypackage 到 Unity

### v1.1 — 核心体验完善

**目标**: 补齐关键体验，把"能用了"变成"好用了"。

**新增**:
- 合并选中文件为同一资产 + 拆开
- 自动从 Booth 下载预览图（默认开启）
- 压缩包目录树解析（.zip/.7z/.unitypackage）
- 识别包内 .unitypackage 并支持一键导入 Unity
- 标签分组 + 多标签组合筛选
- 标签搜索 + 模糊搜索
- 导入进度提示 + 重复检测
- 批量导入时显示包内结构
- 多文件资产详情页（每个文件独立操作）

### v1.2 — 差异化功能

## 8. 非功能需求

### 性能

- 首页加载 ≤ 1s（1000 条资产以内）
- 搜索响应 ≤ 500ms
- 压缩包目录解析 ≤ 3s（1000 文件以内）
- 单文件导入（复制）≤ 2s（100MB 以内）
- 应用冷启动 ≤ 3s
- 支持 5000+ 资产记录不卡顿

### 安全

- 数据完全存储本地
- 不上传用户资产
- 不上传用户的 Booth URL 或个人信息
- 预览图下载仅用于本地展示
- 删除资产时完整清理库文件

### 易用性

- 首次启动引导设置库目录
- 无需网络即可使用核心功能
- 无需注册/登录
- 直觉式操作：拖拽导入、勾选合并、右键操作

### 兼容性

- Windows 10 / Windows 11
- 支持 .unitypackage / .zip / .7z 格式
- Unity 2019+（仅限导入 Unity 功能）
