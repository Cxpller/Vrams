# VRAMS 数据库设计

**版本**: v1.0
**日期**: 2026-07-28
**状态**: 定稿

---

## 1. 设计原则

- **本地 SQLite**，无需远程数据库
- **单库单文件**：`vrams.db` 存放在库目录根目录
- **外键约束开启**：`PRAGMA foreign_keys = ON`
- **版本化管理**：`PRAGMA user_version` 记录 schema 版本，增量迁移
- **不存储文件实体**：文件存磁盘 `assets/{id}/`，数据库只存路径引用

## 3. 表定义

### 3.1 assets — 资产表

一条记录 = 一个用户可见的"资产"（商品）。

```sql
CREATE TABLE IF NOT EXISTS assets (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL,
    source_url  TEXT,
    thumbnail   TEXT,
    notes       TEXT,
    created_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER | 自增主键，同时作为 `assets/{id}/` 目录名 |
| `name` | TEXT | 商品名，用户可编辑。导入时默认取文件名 |
| `source_url` | TEXT | Booth 或官网购买链接，可选，用于追溯来源 |
| `thumbnail` | TEXT | 预览图相对路径，如 `thumbnails/1.jpg` |
| `notes` | TEXT | 用户自由文本备注 |
| `created_at` | TEXT | ISO 8601 格式，如 `2026-07-28 14:30:00` |
| `updated_at` | TEXT | 最后修改时间，每次更新时手动刷新 |

---

### 3.2 asset_files — 资产文件表

一条记录 = 一个导入的文件（.zip / .7z / .unitypackage）。
一个资产可以关联 N 个文件（合并场景）。

```sql
CREATE TABLE IF NOT EXISTS asset_files (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_id      INTEGER NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
    file_name     TEXT    NOT NULL,
    file_size     INTEGER,
    is_primary    INTEGER NOT NULL DEFAULT 0
                          CHECK (is_primary IN (0, 1)),
    file_type     TEXT    NOT NULL DEFAULT 'zip'
                          CHECK (file_type IN ('zip', '7z', 'unitypackage')),
    internal_info TEXT,
    created_at    TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER | 自增主键 |
| `asset_id` | INTEGER → assets.id | 所属资产，级联删除 |
| `file_name` | TEXT | 库目录下的文件名，如 `1/Avatar-Kikyo.zip`。磁盘位置为 `{library}/assets/{file_name}` |
| `file_size` | INTEGER | 文件大小（字节） |
| `is_primary` | INTEGER | 是否主文件（1=是，0=否）。用于卡片展示时确定主类型图标 |
| `file_type` | TEXT | 文件类型：`zip` / `7z` / `unitypackage` |
| `internal_info` | TEXT | JSON 格式的压缩包内文件清单（可选缓存），如 `["Assets/Models/Kikyo.fbx", "Assets/Materials/Kikyo.mat"]` |
| `created_at` | TEXT | 导入时间 |

**关于 `file_name` 的设计说明**：

数据库中存的是相对路径 `{asset_id}/{原始文件名}`，磁盘上对应的完整路径为：
```
{library_path}/assets/{asset_id}/{原始文件名}
```

示例：
```
asset_id = 1, file_name = "1/Avatar-Kikyo.zip"
→ D:/VRAMS-Library/assets/1/Avatar-Kikyo.zip
```

这样做的好处：
- 按 asset_id 组织目录，删除资产时直接删整个目录
- 文件名保留原始名称，用户通过文件管理器查看时认识
- 同一资产的多文件共用一个目录

### 3.3 tags — 标签表

```sql
CREATE TABLE IF NOT EXISTS tags (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT    NOT NULL UNIQUE,
    group_name TEXT    NOT NULL DEFAULT '',
    created_at TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER | 自增主键 |
| `name` | TEXT | 标签名，唯一约束。如 "Kikyo"、"衣服"、"已购买" |
| `group_name` | TEXT | 分组名，用于标签分类展示。如 "角色"、"类型"、"状态" |
| `created_at` | TEXT | 创建时间 |

---

### 3.4 asset_tags — 资产-标签关联表

```sql
CREATE TABLE IF NOT EXISTS asset_tags (
    asset_id INTEGER NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
    tag_id   INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (asset_id, tag_id)
);
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `asset_id` | INTEGER → assets.id | 资产 ID |
| `tag_id` | INTEGER → tags.id | 标签 ID |
| PK | (asset_id, tag_id) | 联合主键，防止重复关联 |

## 4. 索引

```sql
-- 资产：按名称搜索加速
CREATE INDEX IF NOT EXISTS idx_assets_name ON assets(name);

-- 资产：按创建时间排序（首页默认排序）
CREATE INDEX IF NOT EXISTS idx_assets_created_at ON assets(created_at);

-- 文件：按资产查询关联文件（详情页加载文件列表）
CREATE INDEX IF NOT EXISTS idx_asset_files_asset ON asset_files(asset_id);

-- 标签：按分组查询
CREATE INDEX IF NOT EXISTS idx_tags_group ON tags(group_name);

-- 标签名搜索加速
CREATE INDEX IF NOT EXISTS idx_tags_name ON tags(name);

-- 关联表：反向查询（找出某个标签下所有资产）
CREATE INDEX IF NOT EXISTS idx_asset_tags_tag ON asset_tags(tag_id);
```

## 5. 常用查询

### 5.1 首页资产列表（卡片展示）

```sql
-- 分页查询，每页 50 条
SELECT a.id, a.name, a.thumbnail, a.created_at,
       COUNT(af.id) AS file_count,
       MAX(CASE WHEN af.is_primary = 1 THEN af.file_type END) AS primary_type
FROM assets a
LEFT JOIN asset_files af ON af.asset_id = a.id
GROUP BY a.id
ORDER BY a.created_at DESC
LIMIT 50 OFFSET 0;
```

### 5.2 资产详情（含关联文件）

```sql
-- 资产基本信息
SELECT * FROM assets WHERE id = ?;

-- 关联文件列表
SELECT * FROM asset_files WHERE asset_id = ? ORDER BY is_primary DESC, id ASC;

-- 关联标签
SELECT t.* FROM tags t
JOIN asset_tags at ON at.tag_id = t.id
WHERE at.asset_id = ?
ORDER BY t.group_name, t.name;
```

### 5.3 搜索资产

```sql
SELECT a.id, a.name, a.thumbnail,
       COUNT(af.id) AS file_count
FROM assets a
LEFT JOIN asset_files af ON af.asset_id = a.id
WHERE (a.name LIKE '%' || ? || '%' OR a.notes LIKE '%' || ? || '%')
GROUP BY a.id
ORDER BY a.created_at DESC
LIMIT 50;
```

### 5.4 标签筛选

```sql
-- 找出同时包含 标签A AND 标签B 的资产
SELECT a.id, a.name
FROM assets a
JOIN asset_tags at1 ON at1.asset_id = a.id AND at1.tag_id = ?
JOIN asset_tags at2 ON at2.asset_id = a.id AND at2.tag_id = ?;
```

### 5.5 删除资产

```sql
-- 删除资产（ON DELETE CASCADE 会自动清理 asset_files 和 asset_tags）
DELETE FROM assets WHERE id = ?;

-- 磁盘上还需手动删除:
--   {library}/assets/{id}/
--   {library}/thumbnails/{id}.jpg
```

### 5.6 统计信息

```sql
-- 总资产数
SELECT COUNT(*) FROM assets;

-- 总文件数
SELECT COUNT(*) FROM asset_files;

-- 总磁盘占用
SELECT SUM(af.file_size) / 1024 / 1024 AS total_mb
FROM asset_files af;

-- 各标签下的资产数
SELECT t.group_name, t.name, COUNT(at.asset_id) AS count
FROM tags t
LEFT JOIN asset_tags at ON at.tag_id = t.id
GROUP BY t.id
ORDER BY t.group_name, count DESC;
```

## 6. 数据库版本管理

### 6.1 版本记录

```sql
PRAGMA user_version = 1;
```

每次 schema 变更时递增 user_version。

### 6.2 迁移文件规范

```
migrations/
├── V001__init.sql        ← 初始建表
├── V002__add_column.sql  ← 新增字段
└── ...
```

迁移文件要求：
- **幂等**：使用 `IF NOT EXISTS` / `IF EXISTS`
- **编号连续**：不允许跳跃
- **不可修改已发布的迁移**：只能追加新版本

### 6.3 启动时迁移流程

```
应用启动
    │
    ▼
读取 PRAGMA user_version → 假设当前为 0
    │
    ▼
按顺序执行 V001__init.sql → user_version = 1
    │
    ▼
检查下一个 V002... → 不存在 → 迁移完成
    │
    ▼
进入正常逻辑
```

## 7. 数据关系总结

```
一个资产 (assets) ── 有 ── N 个文件 (asset_files)
     │                        ├── assets/1/Avatar-Kikyo.zip
     │                        └── assets/1/Avatar-Kikyo-Hair.zip
     │
     ├── 关联 ── N 个标签 (tags)
     │         └── 通过 asset_tags 多对多关联
     │
     ├── 可选 ── 1 张预览图 (thumbnails/{id}.jpg)
     │
     └── 存储位置 ── assets/{id}/ 目录
```

### 典型数据示例

```
assets 表:
  id=1, name="Avatar-Kikyo 套装", source_url="https://booth.pm/...",
  thumbnail="thumbnails/1.jpg"

asset_files 表:
  id=1, asset_id=1, file_name="1/Avatar-Kikyo.zip",      file_size=57000000,
       is_primary=1, file_type="zip"
  id=2, asset_id=1, file_name="1/Avatar-Kikyo-Hair.zip", file_size=12000000,
       is_primary=0, file_type="zip"

tags 表:
  id=1, name="Kikyo",     group_name="角色"
  id=2, name="衣服",       group_name="类型"
  id=3, name="已购买",     group_name="状态"

asset_tags 表:
  asset_id=1, tag_id=1   -- Kikyo
  asset_id=1, tag_id=2   -- 衣服
  asset_id=1, tag_id=3   -- 已购买
```

## 8. 关于磁盘和数据库的关系

| 数据 | 存哪里 | 说明 |
|------|--------|------|
| 资产名称、URL、备注 | SQLite assets 表 | 纯文本元数据 |
| 文件路径引用 | SQLite asset_files 表 | `file_name` = 相对路径 |
| 标签 | SQLite tags + asset_tags 表 | 纯文本元数据 |
| **原始文件** | **磁盘 `assets/{id}/`** | **不存数据库** |
| **预览图** | **磁盘 `thumbnails/`** | **不存数据库**，只记录路径 |

数据库只记录"指向磁盘的引用"，文件本身通过文件系统管理。
删除资产时：先删磁盘文件 → 再删数据库记录。
