## Task 9.1 — 全流程验收测试

### 任务目标

按用户路径完整走通 MVP 所有功能。

### 涉及文件

- 无（执行测试）

### 测试路径

```
1. [首次启动] 启动应用 → 设置库目录 → 进入首页（空状态）
2. [导入] 拖入 Avatar-Kikyo.zip ↓
   - 导入审查窗口显示包内结构
   - 默认文件名 ✓
   - 确认导入 → 文件复制到库目录
3. [导入] 拖入 Avatar-Kikyo-Hair.zip ↓
   - 勾选 + 合并选中 → 与上一步合并为同一资产
   - 命名"Avatar-Kikyo 套装"
   - 确认导入
4. [导入] 再拖入 3 个不同 zip（不合并）
5. [浏览] 首页显示 4 个资产卡片（1 个合并 + 3 个单文件）
   - 合并资产的卡片显示"2文件"角标
   - 无封面的卡片显示骨架占位
6. [搜索] 搜索"Kikyo" → 找到合并资产
7. [详情] 点开合并资产 → 显示 2 个关联文件
   - 每个文件有"导入 Unity"和"打开文件夹"按钮
8. [标签] 创建标签"Kikyo""衣服""已购买"
   - 为资产打上这 3 个标签
   - 标签按分组展示
9. [编辑] 修改资产名称、填写 Booth URL
10. [预览图] 手动上传一张封面图
    - 卡片封面即时刷新
11. [URL] 点击 Booth URL → 浏览器打开
12. [打开文件夹] 点击"打开文件夹" → 资源管理器定位到文件
13. [删除] 删除一个资产 → 确认 → 资产消失、库目录文件清理
```

### 前置依赖

- Phase 1~8 全部完成

### 验收标准

- [ ] 以上 13 步全部通过，无错误弹窗
- [ ] 每个步骤的操作反馈符合预期

## Task 9.2 — 异常边界处理（文件相关）

### 任务目标

处理导入和操作过程中可能出现的文件异常。

### 涉及文件

- 各处已有代码的容错增强

### 测试场景

| 场景 | 期望行为 |
|------|----------|
| 文件名含特殊字符 `@#$%^&` | 正常导入，文件名保留原样 |
| 文件名超长（>255 字符） | 截断并提示 |
| 文件路径含中文/日文/韩文 | 正常导入 |
| 文件被其他程序占用 | 提示"文件被其他程序占用，请关闭后重试" |
| 磁盘空间不足 | 提示"磁盘空间不足，请释放空间后重试" |
| .zip 文件损坏 | 提示"文件可能已损坏，但可继续导入（无法查看内部结构）" |
| 导入时库目录不存在 | 自动创建或提示 |
| 删除时文件已被手动删除 | 静默跳过文件删除，只清理数据库 |

## Task 9.3 — 异常边界处理（业务逻辑）

### 任务目标

处理业务流程中的边界情况。

### 测试场景

| 场景 | 期望行为 |
|------|----------|
| 导入空文件（0 字节） | 提示"文件为空"并跳过 |
| 导入已存在的文件（相同路径） | 提示"该文件已导入过" |
| 搜索超长关键词（1000 字符） | 正常返回空结果 |
| 编辑时名称设为空 | 前端校验阻止，提示"名称不能为空" |
| 删除时 ID 不存在 | 返回"资产不存在" |
| 打开文件夹时文件已不存在 | 提示"文件已丢失" |
| 连续快速点击"导入 Unity"多次 | 防抖或 loading 状态防止重复操作 |
| 网络不可用时自动下载预览图 | 静默失败，不阻塞用户 |
