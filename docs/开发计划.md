# VRAMS MVP 开发计划

**版本**: v1.0
**日期**: 2026-07-28
**状态**: 定稿
**参考文档**: [产品需求文档.md](./产品需求文档.md)、[系统架构设计.md](./系统架构设计.md)、[数据库设计.md](./数据库设计.md)

---

## 概览

MVP 目标：**让用户能把资产拖进库、打上标签、能找能用。**

| 阶段 | 名称 | 预估工时 | 产出 |
|------|------|----------|------|
| 1 | 项目初始化与环境搭建 | 1 天 | 可运行的空应用 |
| 2 | 数据库与数据模型 | 1 天 | SQLite 初始化 + Rust 模型 |
| 3 | 标签系统（全栈验证） | 1 天 | 标签 CRUD 可用 |
| 4 | 资产导入（核心功能） | 3 天 | 导入审查窗口 + 文件入库 |
| 5 | 资产展示与搜索 | 2 天 | 首页卡片列表 + 搜索 |
| 6 | 资产管理操作 | 1.5 天 | 详情、编辑、删除、打开文件夹、导入 Unity |
| 7 | 预览图与来源链接 | 1 天 | 手动上传封面 + URL 打开 |
| 8 | 首次启动体验 | 0.5 天 | 库目录引导 + 空状态 |
| 9 | 集成验收与边界处理 | 1 天 | 全流程通过 |

**总计预估**: 12 天

| 决策点 | 方案 |

| SQLite Rust 库 | `rusqlite`（简单可靠）或 `sqlx`（异步但复杂度稍高）。MVP 建议 `rusqlite` |
| 7z 解析 | 优先尝试 `sevenz-rust` crate，如不支持则回退到调用 7z CLI |
| 回收站 | Windows `IFileOperation` API，通过 Rust FFI 或 `winapi` crate |
| 图片上传 | 使用 `tauri-plugin-dialog` 打开文件选择器，`std::fs::copy` 到 `thumbnails/` |
| 拖拽导入 | Tauri v2 原生 `onDragDropEvent` 监听 |
| 分页加载 | 前端滚动监听 + 增量加载，后端 `LIMIT 50 OFFSET ?` |
| 防抖搜索 | `@vueuse/core` 的 `useDebounceFn` |
| 状态管理 | Pinia，assetStore + tagStore 两个 store |
